1 · Conceitos de análise de complexidade

Aula 2 — Conceitos

Complexidade de um algoritmo = número de instruções básicas executadas em função do tamanho da entrada.

Premissas da análise

  • Máquina genérica.
  • O custo específico de cada operação é desprezado — “uma instrução é uma instrução”.
  • O efeito dos múltiplos níveis de memória (cache, RAM, disco) não é considerado.
⚠️ Essas premissas são falsas quando um algoritmo precisa ser otimizado para um ambiente específico. É por isso que o mesmo algoritmo pode ter tempos diferentes em ambientes diferentes (questão 17 da lista).

Complexidade espacial × temporal

EspacialTemporal
Quantidade de recursos necessários para resolver o problema: memória, hardware, banda. Quantidade de tempo (ou número de instruções) necessária. Principal fator: tamanho da entrada (n).

Tamanho da entrada (n) = quantidade de itens na entrada (“tamanho do problema” ou da instância). Tempo de execução = quantidade de instruções (cada uma pode levar um tempo diferente na prática).

Melhor, médio e pior caso

  • Melhor caso: a entrada mais favorável.
  • Caso médio: geralmente o que tem maior probabilidade de ocorrer.
  • Pior caso: nosso foco. Existem algoritmos em que o pior caso é o mais frequente (ex.: buscar um item ausente numa lista).

Ordem de crescimento: por que ignorar constantes e termos menores?

Ao comparar algoritmos ignoramos constantes (somas e multiplicações) e componentes de mais baixa ordem. Ex.: c₁n² + c₂n + c₃ = Θ(n²). À medida que n cresce, o termo de maior ordem representa quase todo o resultado.

Exemplo: n² + n

Formalmente: n² + n ≤ 2n² para todo n ≥ 1 (c = 2, n₀ = 1) ⇒ n² + n = O(n²).

2 · Notação assintótica: O, Θ, Ω, o, ω

Aula 2 — Conceitos

Notação assintótica é a linguagem usada para descrever o tempo assintótico de um algoritmo em termos de funções cujo domínio é ℕ = {0, 1, 2, 3, …}. É o vocabulário do projeto e análise de algoritmos. É independente de arquitetura, linguagem ou compilador e serve para comparar algoritmos que resolvem o mesmo problema.

Ela ignora constantes (dependem do sistema) e termos de menor ordem (ficam irrelevantes quando n cresce) e costuma expressar o pior caso por meio de funções T(n).

Θ (Theta) — limite assintótico justo

Θ(g(n)) = { f(n) : existem constantes positivas c₁, c₂, n₀ tais que
0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) para todo n ≥ n₀ }
f(n) fica “espremida” entre dois múltiplos de g(n).

Exemplo do slide: f(n) = 2n² + 100n ∈ Θ(n²) com c₁ = 2, c₂ = 4, n₀ = 50. Conferindo: 2n² ≤ 2n² + 100n sempre; 2n² + 100n ≤ 4n² ⇔ 100n ≤ 2n² ⇔ n ≥ 50.

Contra-exemplo: 6n³ ≠ Θ(n²), pois 6n³ ≤ c₂n² seria falso para n grande.

Para um polinômio de grau d com aₐ > 0: Θ(nd). Constante: Θ(n⁰) = Θ(1).

O (Big-oh) — limite superior

O(g(n)) = { f(n) : existem c > 0 e n₀ tais que 0 ≤ f(n) ≤ c·g(n) para todo n ≥ n₀ }
Para n ≥ n₀, f(n) está abaixo de c·g(n).
  • Θ(g(n)) ⊆ O(g(n)): se f = Θ(g) então f = O(g).
  • n ∈ O(n²) ✔, mas n ∉ Θ(n²) ✘ (O não precisa ser justo).
  • “O tempo de execução no pior caso é O(n²)” vale para qualquer entrada do Bubble Sort. Já a ordenação por inserção pode ser Θ(n) dependendo da entrada.

Ω (Omega) — limite inferior

Ω(g(n)) = { f(n) : existem c > 0 e n₀ tais que 0 ≤ c·g(n) ≤ f(n) para todo n ≥ n₀ }
Se o tempo é Ω(g(n)), ele será no mínimo c·g(n).

Teorema

f(n) = Θ(g(n)) ⇔ f(n) = O(g(n)) e f(n) = Ω(g(n))
Na prática: provamos os limites superior e inferior para demonstrar um limite justo.

o (little-oh) e ω (little-omega) — limites não justos

DefiniçãoExemplos

2n² ≠ o(n²)

n ≠ ω(n)

3 · Recorrências

Como descobrir a complexidade de algoritmos recursivos? Resolvendo recorrências.

Uma recorrência é uma expressão que dá o valor de uma função em termos de valores anteriores da mesma função. É difícil achar o tempo exato de um algoritmo recursivo, mas podemos estabelecer uma recorrência T(n) que descreve esse tempo.

Exemplos

Fibonacci: F(0) = 0, F(1) = 1, F(n) = F(n−1) + F(n−2) para n ≥ 2. (Ordem de crescimento: exponencial.)

Fatorial: fat(0) = 1; fat(n) = n · fat(n−1). O tempo é T(0) = 1, T(n) = T(n−1) + 1 ⇒ T(n) = n + 1 = O(n).

Resolver uma recorrência = achar uma fórmula que dê o valor da função diretamente em termos de n (ex.: n², 2ⁿ, log n).

Toda recorrência precisa de um caso base. Ex.: com F(n) = F(n−1) + 3n + 2, o caso F(1) = 1 dá F(n) = (3n² + 7n)/2 − 4, mas F(1) = 10 dá (3n² + 7n)/2 + 5. Bases diferentes ⇒ soluções diferentes (mesma ordem, Θ(n²)).

Quatro formas de resolver

MétodoCaracterística
SubstituiçãoFormal; abrange todas as recorrências; exige uma estimativa inicial que é provada por indução.
Árvore de recursãoInformal; ótima para obter a estimativa inicial.
Método mestreSimples de aplicar, mas restrito a um conjunto de recorrências (tópico 4).
Divisão e conquistaÉ o paradigma que gera as recorrências (tópico 5).

Prova por indução matemática

Prova a verdade de um número infinito de proposições. Passos: (1) hipótese, (2) passo base, (3) passo indutivo (supor para n, provar para n + 1).

Exemplo do slide: “2n é par”.
Base: n = 1 → 2·1 = 2 (par) ✔.
Passo: supondo 2n par, 2(n + 1) = 2n + 2 = (par) + 2 = par ✔.

Método da substituição

  1. Estimar uma solução.
  2. Provar por indução que a estimativa está correta.

A estimativa vale para limites superiores (O) ou inferiores (Ω). Para limite justo (Θ), prove os dois.

Exemplo completo: busca binária

busca(lista, valor) {
  x = valor do meio da lista
  se valor = x           retorna verdadeiro
  se valor < x           retorna busca(início até x, valor)
  se valor > x           retorna busca(de x até o final, valor)
  senão                  retorna falso
}

A cada chamada, metade da lista é descartada. Como n pode ser ímpar, usamos piso (⌊ ⌋, arredonda para baixo):

T(1) = 1 (caso base)    T(n) = T(⌊n/2⌋) + 1 para n > 1

Resolvendo para n = 2ᵏ (expansão):
T(n) = T(n/2) + 1 = T(n/4) + 2 = T(n/8) + 3 = … = T(n/2ᵏ) + k
Quando n/2ᵏ = 1, ou seja, k = log₂ n: T(n) = T(1) + log n = log n + 1.

Cuidado: isso só vale para n = 2ᵏ, é uma estimativa. Falta provar por indução que T(n) ≤ log n + 1 para todo n:
• Base: T(1) = 1 = log 1 + 1 ✔
• Passo (n > 1): T(n) = T(⌊n/2⌋) + 1 ≤ (log⌊n/2⌋ + 1) + 1 ≤ log(n/2) + 2 = log n − 1 + 2 = log n + 1 ✔
Logo T(n) = O(log n).

Geralmente a estimativa já vem dada na prova — basta provar. Se não vier, “chute” uma e tente provar.

Árvore de recursão

Maneira gráfica de ver as chamadas recursivas. Cada nó é uma instância do problema; se ela chama outras, elas são nós filhos; cada nó é rotulado com o tempo gasto apenas nas operações locais (sem contar as chamadas recursivas).

Exemplo T(n) = 2T(n/2) + n (merge sort):
nível 0:            n                    → custo n
nível 1:      n/2       n/2              → custo n
nível 2:   n/4  n/4   n/4  n/4           → custo n
   ...
nível log n: 1 1 1 1 ... 1               → custo n
São log n níveis, cada um custando n ⇒ total n log n. Esse resultado é o “chute” que depois se prova por substituição (T(n) ≤ c·n·log n).

4 · Método mestre

Receita pronta para recorrências da forma T(n) = a·T(n/b) + f(n).

Condições: a ≥ 1, b > 1, e f(n) deve estar nos inteiros não negativos. “a” = número de subproblemas; “n/b” = tamanho de cada um; f(n) = custo de dividir + combinar.

Passo a passo

  1. Identifique a, b e f(n).
  2. Calcule nlogba (o “custo das folhas”).
  3. Compare f(n) com nlogba:
CasoCondiçãoResultado
1f(n) = O(nlogba − ε) — f cresce menos (polinomialmente)T(n) = Θ(nlogba)
2f(n) = Θ(nlogba) — crescem igualT(n) = Θ(nlogba · log n)
3f(n) = Ω(nlogba + ε) — f cresce mais (polinomialmente) e a·f(n/b) ≤ c·f(n) com c < 1 (regularidade)T(n) = Θ(f(n))

Truque de memória: quem “ganha” a comparação define a resposta; se empatar, multiplica por log n.

Exemplos resolvidos

T(n) = 2T(n/2) + n (merge sort): a=2, b=2, nlog₂2 = n. f(n) = n → empate ⇒ caso 2 ⇒ Θ(n log n).

T(n) = 4T(n/2) + n: nlog₂4 = n². f = n é menor ⇒ caso 1 ⇒ Θ(n²).

T(n) = T(n/2) + 1 (busca binária): a=1, b=2, n⁰ = 1. f = 1 → empate ⇒ caso 2 ⇒ Θ(log n).

T(n) = T(n/2) + n: n⁰ = 1, f = n maior ⇒ caso 3 (regularidade: n/2 ≤ c·n com c = ½) ⇒ Θ(n).

T(n) = 9T(n/3) + n: nlog₃9 = n², f = n menor ⇒ caso 1 ⇒ Θ(n²).

Quando não se pode usar o método mestre

SituaçãoExemplo
Redução por subtração (não é n/b)Fibonacci: T(n) = T(n−1) + T(n−2) + 1
Subproblemas de tamanhos diferentes (não dá pra achar a e b)T(n) = T(n/2) + T(n/4) + n
f(n) não é polinomialmente maior/menor que nlogbaT(n) = 2T(n/2) + n lg n — nlg2 = Θ(n) e n lg n não é polinomialmente maior que n (só um fator log)
a < 1 ou b ≤ 1T(n) = 0,5·T(n/2) + n

Alternativas: método da substituição (funciona para todas), árvore de recursão (para achar a estimativa), expansão/iteração, e o teorema de Akra-Bazzi (generaliza o mestre para subproblemas de tamanhos diferentes).

5 · Divisão e conquista e Merge sort

Aula 4 — “Dividir para conquistar” (Júlio César)

Divisão e conquista é uma abordagem de projeto de algoritmos com as etapas:
1. Divisão: divide o problema em subproblemas, que são instâncias menores do mesmo problema (e cada um é dividido de novo).
2. Conquista: resolve os subproblemas recursivamente e combina as soluções até chegar ao problema original.

Merge sort

  • Criado em 1945 por John von Neumann. Introduz o conceito de dividir para conquistar.
  • Complexidade temporal melhor que seleção, inserção e bubble sort.

Funcionamento:

  1. Divide a lista em sub-listas, e cada sub-lista em novas sub-listas, até que cada uma tenha apenas 1 item.
  2. Conquista: combina (intercala) as sub-listas de forma ordenada — compara os primeiros elementos de cada uma (“quem é menor?”) e coloca o menor na lista resultado, até acabarem.

👉 Veja passo a passo no simulador de merge sort.

Pseudocódigo

mergesort(A, p, r) {
  se p < r então
    q = (p + r) / 2
    mergesort(A, p, q)
    mergesort(A, q+1, r)
    intercala(A, p, q, r)
}
intercala(A, p, q, r) {
  para i de p até q:   B[i] = A[i]
  para j de q+1 até r: B[r+q+1-j] = A[j]   // segunda metade copiada invertida
  i = p;  j = r
  para k de p até r:
    se B[i] <= B[j]:  A[k] = B[i]; i = i + 1
    senão:            A[k] = B[j]; j = j - 1
}

Complexidade

Custos do slide: 1 (teste) + 1 (cálculo de q) + T(n/2) + T(n/2) + (6n + 5) do intercala.
Recorrência: T(n) = 2T(n/2) + n (o termo linear vem do intercala).
• Pela árvore: log n níveis × n por nível = n log n.
• Pelo mestre: caso 2 ⇒ Θ(n log n).
• O slide resolve com as constantes e chega a 16·n·log n ⇒ O(n log n).
O merge sort faz n log n em todos os casos (melhor, médio, pior), mas usa memória extra O(n) (vetor B).

6 · Heap sort

Aula 4 — Criado em 1964 por J. W. J. Williams

Heap é uma estrutura de dados abstrata representada por uma árvore binária (guardada num vetor), com funções simples de manipulação. Implementa filas de prioridade com alta eficiência.
  • Todos os níveis são preenchidos, exceto possivelmente o último, que é preenchido da esquerda para a direita.
  • Num arranjo A: A[1] = raiz; pais sempre ficam à esquerda de seus filhos no vetor.

Índices (slide, vetor iniciando em 1)

Parent(i)Left(i)Right(i)
⌊i / 2⌋2i2i + 1

No código C do slide o vetor começa em 0, então os filhos de i são 2i + 1 e 2i + 2.

Max heap × Min heap

  • Max heap: pai sempre ≥ filhos, A[parent(i)] ≥ A[i]. Usado na ordenação (o maior fica no topo).
  • Min heap: pai sempre ≤ filhos.

Altura de um nó = nº de arestas do caminho mais longo até uma folha. Altura do heap = altura da raiz = ⌊log n⌋. Operações no heap custam no máximo a altura: O(log n).

Algoritmo (código do slide)

heapSort(vet, N) {
  for (i = (N-1)/2; i >= 0; i--)      // 1) constrói o max heap
    criaHeap(vet, i, N-1);
  for (i = N-1; i >= 1; i--) {        // 2) ordena
    troca(vet[0], vet[i]);            //    maior vai p/ posição final
    criaHeap(vet, 0, i-1);            //    conserta o heap (menor)
  }
}
criaHeap(vet, i, f) {                  // "peneira" o nó i para baixo
  aux = vet[i];  j = 2*i + 1;
  while (j <= f) {
    if (j < f && vet[j] < vet[j+1]) j = j + 1;   // escolhe o maior filho
    if (aux < vet[j]) { vet[i] = vet[j]; i = j; j = 2*i + 1; }
    else j = f + 1;                                  // achou o lugar
  }
  vet[i] = aux;
}

Passo a passo

  1. Construir o max heap a partir do vetor desordenado.
  2. Trocar a raiz (maior) com a última folha. O maior está agora na posição correta.
  3. Remover a última folha do heap (o heap encolhe em 1).
  4. O novo topo pode violar a regra ⇒ criaHeap (peneirar): troca com o maior filho enquanto for menor que ele.
  5. Repetir 2–4 até não sobrar nenhum nó. Resultado: lista em ordem crescente.

👉 Veja no simulador de heap sort.

Por que é O(n log n)?

• 1º laço (construção do heap): o slide indica O(n) (são ~n/2 chamadas, e a maioria dos nós está perto das folhas, então peneira pouco).
• 2º laço: n − 1 iterações, cada uma chama criaHeap com custo no máximo a altura, O(log n) ⇒ O((n − 1)·log n).
• Total: n + (n − 1)·log n ⇒ O(n log n).
É n log n no melhor, médio e pior caso. Ordena in-place (memória extra O(1)).
Comparações com outros: mesma complexidade do merge sort; um pouco mais lento que o quick sort no caso médio, porém melhor que ele no pior caso (n log n × n²). Não é recomendado para valores pequenos de n.

7 · Bubble sort e Quick sort

Cobrados na lista de revisão (questões 2, 8 e 9). Resumo para estudo.

Bubble sort

Percorre a lista comparando pares adjacentes e trocando os que estão fora de ordem; a cada passada o maior elemento “borbulha” até o final.

bubble(v, n) {
  para i de 0 até n-2:
    trocou = falso
    para j de 0 até n-2-i:
      se v[j] > v[j+1]: troca(v[j], v[j+1]); trocou = verdadeiro
    se não trocou: pare          // otimização
}
  • Pior e médio caso: O(n²) (dois laços aninhados; lista invertida).
  • Melhor caso: O(n) — só se houver a flag de parada e a lista já estiver ordenada: uma passada sem trocas e termina. Sem a flag, é sempre n².
  • Desvantagem: muito ineficiente para listas grandes (n² comparações e muitas trocas); elementos pequenos perto do fim andam só uma posição por passada.

Quick sort

Escolhe um pivô, particiona a lista (menores à esquerda, maiores à direita) e ordena recursivamente cada lado. Também é divisão e conquista.

  • Caso médio/melhor: O(n log n) — o pivô divide a lista em partes parecidas.
  • Pior caso: O(n²) — quando o pivô é sempre o menor ou o maior elemento (ex.: lista já ordenada ou invertida com pivô = primeiro/último). As partições ficam n−1 e 0 ⇒ T(n) = T(n−1) + n ⇒ n².
  • Como evitar: pivô aleatório, mediana de três (primeiro, meio, último) ou embaralhar a lista antes.
